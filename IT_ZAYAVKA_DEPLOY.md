# Заявка в IT: развёртывание Telegram-бота СРО «ГЕН»

**Тип:** внедрение / эксплуатация инфраструктуры  
**Продукт:** официальный бот для членов СРО (поиск по ИНН, FAQ, ИИ-помощник, справочник)  
**Инициатор (куратор контента):** _____________________  
**Дата:** _____________________

> **Важно:** куратор **не** является системным администратором и **не** штатным разработчиком.  
> **IT:** сервер, запуск, перезапуск, секреты на сервере, бэкапы.  
> **Куратор:** тексты, сценарии, проверка в Telegram, передача **проверенных** обновлений кода.

Подробнее о ролях: `KURATOR_BOT_ROL.md` в комплекте поставки.

---

## 1. Цель

Разместить бота **24/7** на сервере организации (VPS/VDS), чтобы:

- члены СРО пользовались ботом без привязки к рабочему ПК сотрудника;
- **боевой** токен Telegram хранился **у организации**, не у частного ноутбука;
- был **один** процесс бота (иначе Telegram выдаёт ошибку **409 Conflict**).

## 5. Секреты (`/opt/sro-bot/config_keys.py`)

Создать на сервере (права **только root/srobot**, не world-readable):

```python
BOT_TOKEN = "..."           # боевой бот @BotFather, владелец — организация
SRO_FILES_DIR = "/opt/sro-bot/sro_data"
GROQ_API_KEY = "..."        # ключ ИИ (Groq), выдаёт куратор/руководство
CONTACTS_PASSWORD = "..."   # пароль внутреннего справочника — политика СРО
```

Путь **`SRO_FILES_DIR`** на Linux **обязательно** `/opt/sro-bot/sro_data`, не Windows-путь.

## 6. Порядок работ IT (первичный деплой)

1. Создать VPS, настроить SSH, firewall по политике организации.  
2. `mkdir -p /opt/sro-bot`  
3. Загрузить файлы проекта в `/opt/sro-bot/` (архив от куратора или `upload_to_vps.ps1` с рабочей станции, **без** перезаписи prod-секретов с dev-машины).  
4. На сервере: `bash /opt/sro-bot/vps/install.sh`  
5. Создать/проверить `config_keys.py` (п. 5).  
6. Убедиться, что **нигде больше** не запущен бот с **этим же** `BOT_TOKEN` (домашний ПК, другой VPS).  
7. `systemctl start sro-bot` → `systemctl status sro-bot`  
8. Лог: `journalctl -u sro-bot -n 50` — ожидается строка запуска с версией бота.  
9. Проверка в Telegram: `/start`, поиск по ИНН, «ИИ-помощник».  
10. Включить автозапуск: `systemctl enable sro-bot` (делает `install.sh`).

**Куратор на созвоне по SSH не обязателен** — вопросы по **серверу** решает IT; по **логике ответов бота** — куратор.

## 7. Эксплуатация (регламент для IT)

| Действие | Команда / примечание |
|----------|----------------------|
| Статус | `systemctl status sro-bot` |
| Перезапуск | `systemctl restart sro-bot` |
| Остановка | `systemctl stop sro-bot` |
| Лог (50 строк) | `journalctl -u sro-bot -n 50` |
| Лог (онлайн) | `journalctl -u sro-bot -f` |

**Типовые инциденты**

| Симптом | Вероятная причина | Действие IT |
|---------|-------------------|-------------|
| **409 Conflict**, getUpdates | Два процесса с одним токеном | Оставить **только** prod на VPS, остановить дубликаты |
| Бот не отвечает | Сервис упал / нет сети | `restart`, проверить лог, ping api.telegram.org |
| Диск полный | Логи / данные | Очистка, ротация, бэкап |

## 8. Обновление версии бота (после теста куратором)

1. Куратор проверяет изменения на **тестовом** боте (отдельный токен) или по согласованному регламенту.  
2. Куратор передаёт IT: **архив / Git / список файлов** + номер версии (в логе бота, напр. `2026-07-20-v31`).  
3. IT заливает файлы в `/opt/sro-bot/` (**не** затирает prod `config_keys.py` без необходимости).  
4. `systemctl restart sro-bot`  
5. Куратор прогоняет **чек-лист регрессии** (раздел **13**) в **боевом** Telegram.

**Доступ куратора (согласовать с IT):** один из вариантов — Git-репозиторий организации; SFTP/SSH только на каталог кода; или «куратор → zip → IT заливает».

## 13. Регрессия после обновления (куратор, ~3 минуты)

**Когда:** после каждой выкладки на prod (и желательно на **тестовом** боте до выкладки).

**Версия:** в логе сервера или консоли при локальном запуске должна совпадать с переданной IT (напр. `2026-07-20-v38`):

```text
journalctl -u sro-bot -n 20
# или строка «Бот запускается... (2026-07-20-vXX)»
```

**Как проверять:** из главного меню, **без** режима «Поиск организации», обычным текстом (как пишет член СРО).

**На ПК до Telegram:** `python routing_regression.py` — автопроверка маршрутизации по типовым фразам из таблицы.

| № | Отправить боту | Должно быть | Не должно быть |
|---|----------------|-------------|----------------|
| 1 | `Филина` | Поиск в **телефонном справочнике** (найден / не найден — по базе) | Ссылка на **филиалы**; «внутренняя ошибка сервера» |
| 2 | `телефон Миронова` | **Справочник**, карточка сотрудника или «не найдено» | Ответ про раздел «Контакты» на сайте вместо справочника |
| 3 | `Берестовская` | **Справочник** (не поиск организации в реестре) | Карточка **ООО** / «организация не найдена» |
| 4 | `где устав` | **ИИ / сайт**: документы СРО, ссылка на srogen.ru | «В справочнике никого не найдено» |
| 5 | `стандарты и правила СРО` | **ИИ / сайт**, раздел документов | Справочник |
| 6 | `база законов` | **ИИ / сайт**, законодательство | Справочник |
| 7 | `техрегулирование` | **ИИ / сайт**, техрегулирование / регламенты | Справочник |
| 8 | `размеры взносов` | **ИИ / сайт**, таблица взносов (тема `vznosy`) | Ответ про **НОСО / партнёров** |
| 9 | `еврокоды что это` | **FAQ**, кратко про Еврокоды + voprosy | «Точного ответа нет» |
| 10 | *(ИНН из тестовой базы)* | Карточка организации, план проверок | — |
| 11 | `/start` | Главное меню, кнопки на месте | Зависание, пустой ответ |

**Дополнительно (раз в релиз или по изменениям):**

- [ ] «📞 Контакты отделов» → пароль → отдел → список сотрудников  
- [ ] «🤖 ИИ-помощник» → короткий вопрос с «?» → ответ со ссылкой на сайт  
- [ ] «🔍 Поиск организации» → ИНН → только реестр, **без** ухода в справочник по ФИО  

**Если пункт не соответствует таблице:** скрин + текст запроса + **версия из лога** → куратор (логика) или IT (409, не стартует сервис).
