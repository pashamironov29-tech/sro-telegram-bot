## Чеклист на каждый месяц (октябрь и далее)

В Word по каждому СРО должны быть **все четыре** типа отметок:

| # | Что | Как в Word |
|---|-----|------------|
| 1 | **Свежий реестр** | list-only всех 15 СРО в тот же день (до проверки) |
| 2 | **Исключённые** | 🔴 `(исключена)` |
| 3 | **Проверки 2026** | 🟡 `(1 проверка в 2026)` / 🟠 `(N проверки/проверок в 2026)` |
| 4 | **Задвоения** | 🔴 `(Организация задваивается)` |

Без `--live` проверки 2026 **не** подтянутся. Без полного list-only задвоения видны только по тем СРО, что успели обновить.

---

## Зачем

Перед публикацией плана на месяц вручную долго: по каждой организации смотреть в реестре СРО — **не исключена ли**, **сколько проверок в 2026**, **не задваивается ли**. Скрипт делает это пакетом.

**Важно:** агент **не удаляет** строки из плана сам. Только подсвечивает и пишет причину в скобках — решение за тобой.

## Откуда что берётся

| Что | Где лежит | Зачем |
|-----|-----------|--------|
| **Планы на год (Word)** | `sro files/plany/*.docx` | Список организаций по месяцам (январь…декабрь) для каждого СРО |
| **Путь к папке** | `config_keys.py` → `SRO_FILES_DIR` | На каждом ПК свой путь (`User` / `pasha`) |
| **Реестр СРО (кэш)** | `reestr_cache.json` | ИНН, статус «Член СРО» / «Исключен», членство по 15 СРО |
| **Живые карточки** | Сайты СРО (через `reestr_sync.py`) | История проверок по годам (`inspections_by_year`), в т.ч. **2026** |
| **Связка файл → СРО** | `reestr_sync.py` → `PLANY_FILE_TO_SRO` | Например `ogpp_2026.docx` → ОГПП |

Планы **не** из Excel «ИТОГИ КОНТРОЛЯ» — это уже готовые годовые `.docx` в `plany/`. Сборка таких файлов из Excel — отдельно (`plan_proverok_export.py`).

## Как идёт проверка (по шагам)

1. **Свежий реестр (list-only)** — обязательно перед проверкой, чтобы статусы «Исключен» были актуальными.
2. **Выбираем месяц** (например, сентябрь) и при необходимости **какие СРО не трогаем** (у Паши не свои планы: ОСОВС, ОСОТ, НОСО, ОСОЕС).
3. **Читаем** все `*.docx` в `sro files/plany/`, в таблицах ищем блок месяца и строки с ИНН.
4. **Проверка по обновлённому кэшу** + при `--live` карточки на сайтах:
   - статус ≠ «Член СРО» → `(исключена)` (в т.ч. из дисциплины на карточке);
   - **задвоение** (один ИНН — две карточки в одном СРО) → `(Организация задваивается)` вместо просто «исключена»;
   - считаем **сколько строк** проверок за год.
5. **Пометки в Word:**
   - 🔴 `(исключена)` — скорее убрать;
   - 🔴 `(Организация задваивается)` — смотреть обе карточки в реестре;
   - 🟠 `(2 проверки в 2026)` и больше — **сначала смотреть в своей базе**, какая была плановая;
   - 🟡 `(1 проверка в 2026)` — на заметку: если это жалоба/текущий контроль — **оставить в плане**; убирать только если была **плановая**.

**Главное правило Паши (27.07.2026):** из плана убирать только после **плановой** проверки. Проверка по жалобе или текущему контролю в 2026 — организация в план **всё равно** идёт. Сайт этого не различает — решение по базе.

## Скрипт для повтора (полный цикл)

```powershell
cd "C:\Users\User\OneDrive\Рабочие\GOLD"
$env:PYTHONIOENCODING="utf-8"

# Шаг 1: реестр + live-карточки → JSON с отметками
py scripts/plan_month_check.py --month октябрь --skip-sro ОСОВС,ОСОТ,НОСО,ОСОЕС --live --out plan_check_октябрь_flagged.json

# Шаг 2: Word по СРО (УТВЕРЖДАЮ, автонумерация, подсветка)
py scripts/export_month_plans_docx.py --month октябрь --skip-sro ОСОВС,ОСОТ,НОСО,ОСОЕС --flagged plan_check_октябрь_flagged.json --out "C:\Users\User\Desktop\Планы_октябрь_2026_Word_утв"
```

По умолчанию `scripts/plan_month_check.py` **сначала** обновляет реестр list-only (~30–40 мин), потом при `--live` качает карточки (~40–45 мин).  
`--no-fresh-reestr` — только если list-only всех 15 СРО уже в этот же день.

Результаты:
- `plan_check_<месяц>_flagged.json` — кого и почему отметить;
- папка на рабочем столе — отдельный `.docx` на каждое СРО.

**Нумерация в Word** — автоматическая: удалишь строку, номера сами пересчитаются.

## Ограничения (честно)

- Кэш реестра **без** `--live` не покажет проверки 2026 — нужен `--live`.
- Задвоения (`duplicated`) появляются только после **полного** list-only всех СРО, не одного ОГПС.
- Сайты обновляются **примерно раз в сутки** — накануне плана лучше живая проверка.
- Один ИНН в нескольких СРО — смотрим **членство в том СРО**, к которому относится строка плана.
- Имена в плане иногда кривые («ООО») — ориентир **ИНН**.
