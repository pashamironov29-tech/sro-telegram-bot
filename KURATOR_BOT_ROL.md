# Роль куратора Telegram-бота СРО «ГЕН»



**Для согласования с руководством**



---



## Для руководства — на одной странице



**Кто я по факту:** не программист и не IT-штат. Я **куратор бота** — человек от Ассоциации, который знает процессы СРО и то, что должны получить члены в Telegram.



**Как бот появился:** сценарии, меню, FAQ, ИИ-помощник и правки делаются **с помощью ИИ-инструментов** (описание задач словами, проверка в боте, исправление по скринам). Это современный формат «сделать продукт без классической разработки в штате», а не курс программирования.



**За что я отвечаю (моя зона):**



- *что* бот говорит и *куда* ведёт (сайт, бланки, FAQ, справочник по правилам Ассоциации);

- актуальность контента по вашим материалам;

- проверка после изменений («работает / не работает» для пользователя);

- согласование новых функций с руководством.



**За что я не отвечаю (не моя зона):**



- «держать код в голове», архитектура, сервер 24/7, как у штатного разработчика;

- юридические консультации и решения по спорным кейсам — их дают специалисты СРО;

- индивидуальная ответственность за uptime без выделенной IT-инфраструктуры.



**Что нужно от Ассоциации:** понимание, что роль — **управление цифровым сервисом для членов**, а не должность «программист». При необходимости сервер, бэкапы и сложный IT — отдельно IT или подрядчик; куратор ставит задачи и принимает результат.

## 1. Как назвать роль



**Куратор / product-owner официального бота Ассоциации в Telegram**



- Не «разработчик в штате», а **владелец сценариев**: что бот должен отвечать, кому, чего не делать (конфиденциальность, юридические формулировки).

- **Создание и доработка бота** — через ИИ-ассистента по ТЗ куратора; **ответственность за смысл и качество для пользователя** — на кураторе, **не за строки программного кода** как у программиста.

- **Приёмка и регрессия** (прогон сценариев в Telegram) — на кураторе.

## 3. Зона ответственности куратора



1. **Контент и логика** — актуальность FAQ, формулировки, ссылки на srogen.ru, списки партнёров и отделов (по данным Ассоциации).

2. **Доступы** — пароль справочника, кому выдаётся; не публиковать токены и ключи.

3. **Тестирование** — прогон **чек-листа регрессии** после каждого обновления (раздел **6** ниже; полная таблица для IT — `IT_ZAYAVKA_DEPLOY.md`, раздел **13**).

4. **Обратная связь** — сбор замечаний от членов СРО и сотрудников, приоритизация доработок.

5. **Согласование** — новые функции (например, «обратный звонок / заявка») только после решения руководства.



**Не входит в роль без отдельного договора:** написание и сопровождение программного кода «как у разработчика», круглосуточная эксплуатация сервера, юридическая экспертиза ответов бота, замена юристов/кураторов СРО.



---



## 4. Чем куратор отличается от «программиста»



| Куратор | Программист в штате |

|---------|---------------------|

| Знает процессы СРО и ожидания пользователей | Пишет и рефакторит код под ТЗ |

| Формулирует задачи словами, проверяет в Telegram | Проектирует архитектуру, CI/CD, безопасность |

| Дорабатывает бот **с ИИ**, отвечает за продукт | Отвечает за код и инфраструктуру |

| Ведёт регрессию «как пользователь» | Отвечает за uptime VPS, мониторинг, бэкапы |



Совместная модель: **куратор = product + QA**, **IT/подрядчик = инфраструктура и сложные доработки** при необходимости.

## 5. Предложение по оформлению (для переговоров)



- **Должность / доп. функция:** куратор официального Telegram-бота СРО «ГЕН».

- **Объём:** поддержание актуальности сценариев, приёмка обновлений, связь с аппаратом по контенту (контакты, FAQ, партнёры).

- **Ожидаемый эффект:** меньше повторяющихся звонков и писем; единая «точка входа» в цифровые сервисы Ассоциации в мессенджере.

- **Инструменты:** рабочий ПК/ноутбук для тестов и правок контента; доступ к материалам Ассоциации (справочник, бланки, согласованные тексты).



*Конкретные цифры (градация, доплата, техника) — по внутренней политике; документ фиксирует **суть роли**, а не HR-решение.*

## 6. Чек-лист регрессии после обновления (~3 минуты)



**Зачем:** при правках маршрутизации (справочник ↔ ИИ ↔ сайт) новые темы не должны ломать то, что уже работало. Прогон — **обязанность куратора** перед «можно в prod» и сразу после `restart` на сервере.



**Перед прогоном:** убедиться, что в логе/консоли актуальная **версия** бота (напр. `2026-07-20-v38`).



| Отправить | Ожидание |
|-----------|----------|
| `Филина` | Справочник (не «филиалы», не ошибка сервера) |
| `телефон Миронова` | Справочник |
| `Берестовская` | Справочник, не поиск **организации** |
| `где устав` | ИИ / ссылка на документы СРО |
| `стандарты и правила СРО` | ИИ / сайт |
| `база законов` | ИИ / законодательство |
| `техрегулирование` | ИИ / техрегулирование |
| `размеры взносов` | ИИ / взносы (не партнёр **НОСО**) |
| `еврокоды что это` | FAQ про Еврокоды |
| Тестовый **ИНН** | Карточка в реестре |
| `/start` | Меню на месте |



**Не OK:** ответ «🔍 … в телефонном справочнике никого не найдено» на строки из середины таблицы (устав, законы, техрегулирование и т.п.).



Полная таблица «должно / не должно», пункты по меню и контактам — **`IT_ZAYAVKA_DEPLOY.md`, раздел 13**.

Перед выкладкой на сервер: **`python routing_regression.py`** в папке GOLD.

## 7. Риски, о которых важно знать руководству



- **Один активный экземпляр бота** на токен — иначе Telegram блокирует опрос (ошибки 409 / polling).

- **Конфиденциальный справочник** — только с паролем; утечка пароля = риск для внутренних данных.

- **ИИ не консультант** — только навигация по сайту и типовым FAQ; спорные случаи — телефон Ассоциации.
